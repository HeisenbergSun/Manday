# Manday 产品细节优化方案

> 基于 Monday.com 设计思路专项调研（9 个维度：信息架构 / 列体系 / 视图体系 / 条目交互 / 自动化 / 权限模型 / 通知协作 / 新手引导 / 视觉语言），结合 Manday 现状（NestJS + Postgres JSONB + React，自研表格 / 甘特 / 列级权限 / 回收站 / 历史版本已落地）整理。

## 一、Monday 的三个核心设计分离（指导原则）

Monday 产品的所有细节都服务于三个"分离"：

1. **内容与结构分离** —— 编辑数据（改 cell 值）和编辑看板结构（加列、改列、删组）是两种能力、两种权限。我们目前的权限是"整板一刀切"，这是最大的差距。
2. **沟通与数据分离** —— Updates（对话流）和 Subitems（结构化子任务）是两个东西：前者记录讨论，后者承载可勾选的执行项。我们已有 Subitems，但 Updates 与子任务、历史混在一个详情面板里，没有语义分层。
3. **个体偏好与团队配置分离** —— 视图的"存在和顺序"是看板级配置（owner 管），视图里的"筛选/排序/分组"是个人偏好（每人自己存，互不影响）。我们目前只有看板级视图。

## 二、P0 —— 快赢项（1~2 天/项，纯体验提升）

| # | 优化点 | Monday 做法 | Manday 落地方式 |
|---|--------|------------|----------------|
| 1 | Status 默认标签 | 新建 Status 列自动带 Done/Working on it/Stuck 三标签 + 灰色默认值 | 新建 status 列时 seed 默认 settings.labels（Done 绿/Working 黄/Stuck 红），新 cell 默认灰色 "–" |
| 2 | 标签 Deactivate | 删除旧标签不破坏历史数据，只是"停用" | board_columns.settings 加 `inactiveLabels`，删除标签=移入停用，旧值照常展示 |
| 3 | is_done 语义位 | Monday 所有视图都识别"完成"状态（甘特变灰、看板折叠） | item_values 加 is_done 判断逻辑（status 值在 settings.labels.done 指向的标签集合内），甘特条完成变灰、看板可折叠 done 组 |
| 4 | 底部浮动批量工具条 | 选中 3+ 行后底部浮出操作条（改状态/加粗/删除/归档） | Grid 检测 selection.length ≥ 3 时显示 fixed bottom bar：改 status / 删除进回收站 / 清除所选 |
| 5 | hover 行 Open 按钮 | 行尾 hover 出现 "Open" 链接打开详情 | Grid 行 hover 显示 Open 按钮，替代"双击行"的隐式交互 |
| 6 | 详情面板三 tab | Updates（讨论）/ 子任务 / 活动（历史）分区 | 详情面板拆三个 tab：Updates（空态引导"用 @ 提及同事"）、子任务（已有）、历史（五段式展示，见 P1-6） |
| 7 | 表格快捷键 | Monday 无捷径靠快捷键：Enter 打开、Space 勾选、M 改人员、Esc 关闭 | Grid 全局 keydown：↑↓导航、Enter 开详情、Space 勾选、Esc 关闭面板/取消编辑 |
| 8 | 双色 token 分离 | 标签色（数据语义）与 UI 主色（品牌）严格分离 | CSS 变量拆 `--tag-*` 与 `--ui-*` 两套，避免改主题时污染数据颜色 |
| 9 | 通知统一落点 | 通知 = @提及 + 分配 + 订阅，全部收敛到一个铃铛 | 铃铛面板分区：提及我的 / 分配给我的（item assignee 变更）/ 我订阅的看板有更新 |

## 三、P1 —— 核心能力（3~5 天/项，能力补齐）

1. **编辑内容 vs 编辑结构权限拆分**：board_members 增加 `canEditContent`（默认 member 有）与 `canEditStructure`（仅 owner）两级。updateItem/updateCell 走前者，addColumn/reorder/deleteColumn 走后者。这是 Monday 权限模型的地基。
2. **列权限互斥：限制编辑 vs 限制查看**：现有 `editable='owner'` 扩展为 `editPermission: all|owner` + `viewPermission: all|owner`，两者互斥生效；查看受限列对无权成员显示 "🔒 Pro 资产" 风格的模糊占位（Monday 隐藏 cell 内容但保留列宽）。
3. **视图锁定/固定**：owner 可锁定视图配置（filter/group/sort 写死），普通成员只能看不能改；锁定视图排前固定。`board_views.settings.locked` 布尔位即可。
4. **视图筛选/排序个人偏好分离**：`board_views`（看板级：类型/名称/顺序/锁定）与 `view_preferences`（user_id + view_id：filter/sort/group）拆表。同一视图每人看到自己的筛选。
5. **可编辑甘特 + 依赖**：甘特条拖拽改起止日期（写回日期列），条间连线表示依赖（dependsOn 列），A 完成 B 解锁（配合 P0-3 is_done）。先做拖拽改期，依赖二期。
6. **五段式历史**：详情历史 tab 改为 Monday 式分段——「谁 / 何时 / 改了什么字段 / 从什么值 / 到什么值」，现为 `changed: {field: {old, new}}`，前端按字段渲染成句子："张三 把 状态 从 Done 改为 Stuck"。
7. **看板列绑定 Status**：Kanban 视图可选择某 status 列作为泳道（ Monday 看板本质是 status 列的另一种渲染），列头显示每泳道 count 与 done 折叠。
8. **Workload 轻量视图**：按 assignee 聚合条目数量/工作量列，横向条形图（每人一行），不做复杂资源日历——先给"谁身上压了多少活"的一眼可见。
9. **句子式自动化**：`when [状态变为 Done] then [通知 / 改字段 / 移动到组]`。先支持 3 个模板：状态变 Done→通知 assignee、每到期日→提醒、加人到看板→通知 owner。规则存 `automations` 表，items service 里事件钩子触发。

## 四、P2 —— 远期项（视需求排期）

1. **问卷式新手引导**：首次登录 3 问（团队规模/主要用途/想先看哪个模板），按答案预置看板模板 + 示例数据，替代干巴巴的空看板。
2. **模板预置示例数据**：每个模板（项目跟踪/销售管道/排期）自带 5~10 条样例条目，可一键删除；空看板留存率杀手。
3. **Formula 列**：基于列引用的只读公式列（`{预算}-{已花}`），先支持四则运算 + SUM/COUNT 聚合。
4. **Mirror 列**：跨看板引用条目（Connect boards 后镜像对方状态），依赖 connect 关系表。
5. **视觉低饱和收敛**：标签色整体降饱和（Monday 用 `#579bfc` 类柔和蓝而不是纯 #1890ff），组背景用极浅色带，减少大面积高饱和填充。

## 五、不建议照搬的 Monday 设计

- **复杂视图家族（Chart/Workdoc/Whiteboard）**：投入大、非刚需，Manday 四视图（表格/看板/甘特/Workload）已覆盖 90% 场景。
- **完整 Updates 社交流（点赞/GIF/表情回复）**：200 人规模先用文本 Updates + @提及，够用。
- **Monday 端到端自定义自动化 DSL**：句子式模板先行，DSL 复杂度远超当前阶段。

## 六、建议实施顺序

1. 第一周：P0 全部 9 项（多数是前端改动，P0-1/2/3 需少量后端配合）
2. 第二周：P1-1、P1-2（权限拆分——数据模型变更宜早不宜迟）、P1-6（历史五段式，纯前端）
3. 第三周起：P1-3/4（视图体系重构）、P1-9（自动化）
4. P2 在以上稳定后按用户反馈排期
